授業内ハッカソン＋宿題In-class hackathon + homework

天気ハッカソンWeather Hackathon

天気予報を使って、誰かの「いつ・どうする？」に視覚的に答えるNotebookを作ろう。2〜3人で制作し、最後に全チームが実演する。Build a weather-assistant notebook with a visual answer to someone’s question. Work in teams of 2–3 and give a short demo at the end.

完成品・必要なものFinal deliverable and requirements

  • 誰が、何を決めるための道具かをMarkdownで書く。Explain the user and the decision in Markdown.
  • APIの予報をforとifで調べ、自分たちの条件で時間を選ぶ。Use for and if to select forecast hours using your own rule.
  • 条件に合わせて変わる視覚表示を一つ。表・グラフ・地図など。Include a visual that responds to the settings: a table, chart or map.
  • whileで繰り返し使え、quitで終了できるようにする。Use while to let the user try again and quit to finish.
  • 設定を2通り試し、結果に基づく提案とデータの出典を記す。Try two settings. Add a recommendation and the data source.

作り方・教材How to build / files

  1. スターターでAPIの予報を読み込む。Load the API forecast with the starter notebook.
  2. 誰に役立つかを決め、for＋ifの条件を変える。Choose a user and adapt the for + if rule.
  3. 結果を見せ、whileで条件を変えて繰り返せるようにする。Show the result and use while to let the user try again.
  4. 動作を確かめ、Notebookに説明を書く。Check it works and explain it in Markdown.

ZIPを解凍し、challenge-starter.ipynbの最初の2つのコードセルを実行。追加インストール・pandas・APIキーは不要。表示コードはそのまま使える。Unzip the pack and run the first two code cells in challenge-starter.ipynb. No extra packages, pandas or API key. Use the supplied display helper.

アイデアIdeas

  • 自転車通学：「雨が少なく、寒すぎない時間は？」Cycling to campus: “When is it dry enough and warm enough?”
  • サークル：「外で練習するなら、何時がよさそう？」A club: “What time looks good for outdoor practice?”
  • 自分たちで、別の使い方を考えてもよい。Your team can choose another use for the forecast.

グループの進め方Good group work

  • 最初に、使う人と目的を全員で決める。Agree on the user and the question before coding.
  • コードを書く・結果を確かめる・表示と説明を整える。得意なことを分担し、困ったら一緒に考える。Share the coding, checking and visual explanation. Help each other when someone gets stuck.
  • 全員がコードの変更に参加し、その変更を説明できるようにする。Everyone contributes a code change and understands what it does.
  • まず小さく動かす。変更を一つずつ確かめ、発表前に全員で実行する。Get a small version working. Check one change at a time and run the notebook together before presenting.

AIはエラーの説明や小さなヒントに使ってよい。作品全体を任せず、使ったコードは全員で読み、結果を自分たちで確かめる。AI can explain an error or give a small hint. Keep the build in your hands: read the code together and check its results yourselves.

困ったときのヒントHints if you get stuck
  • 通信エラー：ZIPの中身を同じフォルダに置き、保存JSONで続ける。Connection error: keep the unzipped files together and use the saved JSON.
  • 結果が0件：条件を少し緩める。0件という結果も伝えよう。No matches: relax a condition and explain when nothing matches.
  • 入力セルが終わらない：quitと入力する。Input cell still running: enter quit.
  • 最初は値を一つだけ変える。条件と結果のつながりを説明しよう。Change one value first and explain how it affects the result.

最後に、全チームが実演Every team demos at the end

14:25から20分。1組60〜90秒を目安に調整。Notebookをそのまま見せる。別の発表スライドは不要。Twenty minutes from 14:25. Aim for 60–90 seconds per team, adjusted to the number of teams. Present from the notebook, with no separate slides.

  1. 誰の、何を助ける？目的を一文で。State whose decision your tool helps.
  2. 視覚表示を見せ、条件を変えてもう一度動かす。Show the visual, change a setting and run it again.
  3. for・if・whileの一行を説明し、分かったことを話す。全員が一言話す。Explain a line using for, if or while and one finding. Everyone speaks briefly.
